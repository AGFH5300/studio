# Astra and interactive-experience research

Research date: 6 September 2026. This file preserves completed research so later sessions do not repeat it.

## Evidence standard and limits

**V = visually inspected:** extracted video contact sheets or a retrieved image were actually viewed. This verifies visible composition and depicted UI, not the code, true frame rate, usability, scene completeness or whether the recording was edited.

**C = creator-reported:** original author post, available through indexed original post or public FxTwitter metadata mirror. Claims about time, autonomy, model effort, asset origin and size remain claims unless independently tested.

**P = primary build write-up:** an original, opened technical account with implementation details and prompts. Stronger workflow evidence than a highlight reel; it is still the author's account.

**I = inference / Veya recommendation:** our interpretation, not a factual claim about another builder.

Seven supplied videos were retrieved before interruption and contact sheets created; B had already been inspected. On resumption A/C/D/F/G/H sheets were inspected. Some source MP4 sizes differed from the earlier download log after the interrupted session, so completeness of surviving raw videos is not certified. No inference of continuous playback quality is made. Saved contact sheets are the actual visual evidence used. They are reference material, not licensed production assets.

E's supplied `.mp4` URL failed because the associated post contains images, not a video. Its public metadata and reference-collage image were retrieved and inspected. No need to repeat this discovery.

## Required references A–H

### A — SahilExec: Death Star experience (V, C)

[Original post](https://x.com/SahilExec/status/2094044336921235811). [Supplied video](https://fxtwitter.com/SahilExec/status/2094044336921235811.mp4). Visual record: `references/A.jpg`.

**Observed:** a title/control view, metallic corridors, repeated luminous wall strips, an in-world console and an exterior spherical station. Strong depth comes from repetition, perspective and contrasting lit/dark regions. Controls include exterior/interior modes; the depicted experience contains more than one camera context. Tiny labels and deep darkness would be weaknesses for Veya’s business information.

**Creator claim:** 75K tokens, 26 minutes, maximum effort. No detailed pipeline in this post. Do not infer Blender, physics or performance from its appearance.

**Adopt:** consistent construction grammar across near and far views; meaningful interaction modes. **Reject:** first-person corridor traversal as the route to pricing. Do not extrapolate this author’s timing to Plus usage.

[Original post identified](https://x.com/mvkaran/status/2096249702937460876). [Supplied video](https://video-s.twimg.com/amplify_video/2096247909591531520/vid/avc1/1920x1080/IilJhKKjYflfofIo.mp4). Visual record: `references/B.jpg`.

Composition changes between wide structure and intimate ornament. The excerpt is not evidence of survey-accurate reconstruction.

**Adopt:** finished/inside states of one object, named camera destinations, large-to-small detail hierarchy. Veya's unfold must reveal real business functions, not merely explode attractive parts. Audio in a posted video does not prove a valuable website sound requirement.

### C — Anshu: Afterlight, favorite reference (V, C)

[Original](https://x.com/anshuc/status/2096008083826725132), [workflow continuation](https://x.com/anshuc/status/2096008086901113339). Visual record: `references/C.jpg`.

**Observed:** oblique courtyard scenes, rain-dark paving, layered walls, pipes, foliage, warm windows, a small character and contextual interaction panels. Quiet architecture frames the playable ground; a local map and labels orient the user. Surface variation and occlusion make repeated blocks feel inhabited. This is richer than an isolated 3D prop because foreground, playable area and background belong together.

**Creator claim:** generated concept targets, Blender MCP, screenshot matching toward a 60fps goal, high reasoning, Blender-authored assets and generated textures. Reported 45 minutes and low quota use are not transferable guarantees.

**Adopt:** save an art target; compare actual runtime frames with it; build a coherent kit with physical lighting. For Veya, replace walking objectives with changing and testing a digital project. Preserve agency and layered composition without copying dystopia, voxel styling or game UI.

## Strongest original workflow write-ups

### Solace / architectural visualization (P)

[Thomas Ricouard, OpenAI, 4 September 2026](https://developers.openai.com/blog/architectural-visualization-with-astra).

The account describes a Blender Python workflow, preview-render corrections, a floor-plan checkpoint before expansion, geometry-only inspection, authored furniture detail, and selected Poly Haven assets. It separates model validation from Unreal transfer. Saved camera studies expose problems hidden in broad cinematic views.

**Veya application:** approve the object's structure and working constraints before adding materials. Maintain editable source assets and a reproducible export. Inspect untextured hinges and intermediate poses, not just the most flattering final frame. Use sourced assets for generic background needs only when they save effort without defining the identity. This is a phased workflow even when the first brief is short.

### Void Explorer / building games (P, additional Astra example)

[Thomas Ricouard, OpenAI, 4 September 2026](https://developers.openai.com/blog/how-to-build-games-with-astra).

The author sets a concrete interaction promise, refines generated concept images, and saves reference targets. The build separates simulation from rendering, uses named test situations, exposes diagnostic state/counters, and tests real journeys in addition to screenshots. Rendering evolved without replacing the underlying simulation.

**Veya application:** name the Fold's key states; expose development-only diagnostics; test both fixture screenshots and the real sequence of choices that reaches them. Keep estimator logic independent of appearance. A screenshot at the destination cannot prove that a transition, Undo or stale-state recovery works.

### Architecture Studio (P, additional Astra example)

[OpenAI showcase](https://developers.openai.com/showcase/architecture-studio).

A shared room document powers editable 2D and synchronized 3D views; the published workflow includes furniture creation, control refinement, export and mobile panel adaptation. This is particularly relevant because spatial appeal is attached to a real planning task.

**Veya application:** one scope document powers the accessible questions, Fold, summary and share output. Geometry does not become the data model.

### Ridge Pack (P, additional Astra example / configurator)

[OpenAI showcase](https://developers.openai.com/showcase/ridge-pack).

The published prompt specifies a useful packing guide, a bounded dimensional model, consistent visual/fit feedback, tap alternatives to dragging, removal/Undo and testing at capacity boundaries. It also separates interactive utility from accounts or runtime AI dependency.

**Veya application:** a configuration must obey its underlying rules; an appealing animation cannot imply that a conflicting or unpriced capability is included. Translate “fit” into approved package eligibility and transparent scope-review states.

## What strong builders appear to do differently

1. Specify a meaningful user action and a visual outcome, then let architecture serve them.
2. Create and retain visual targets instead of asking repeatedly for “more premium”.
3. Give the agent real tools for assets, rendering and inspection; make tool access explicit before a session starts.
4. Use modular geometry and reusable materials; buy or source generic detail when sensible.
5. Inspect structure, material, composition and runtime behavior separately.
6. Provide repeatable scenes and observable state so visual debugging is cheap.
7. Preserve source files and approved stages, then refine the highest-impact weaknesses.
8. Distinguish playable quality from trailer quality, and headline asset size from full delivery cost.

These are a synthesis of the sources above, not a universal recipe or a claim that one prompt guarantees excellence. Veya's exact iteration protocol is in development-plan.md. No Plus quota, five-hour allowance or elapsed-time guarantee is inferred from creator anecdotes.
