## Exact visual-development loop

1. **Resume:** read handoff and latest session-log; inspect only changed files and current artifacts. Confirm objective and available tools, not a fresh research campaign.
2. **Define a shot/behavior contract:** fixture, viewport, seed, camera, selected scope, lighting, target reference and expected interaction. Record what success looks like in 3–5 observable criteria.
3. **Block structure:** verify silhouette, hierarchy, pivots and geometric envelope in clay/neutral materials. Do not hide geometry errors in atmosphere.
4. **Set art target:** pick one concept direction; save it. Improve composition/light/material in separate passes so causes stay understandable.
5. **Run actual browser:** reach state with both a reproducible fixture and real controls. Capture screen, intermediate animation poses, short recording, console and counters. Use a neutral/reduced-motion comparison when useful.
6. **Critique concretely:** identify at most three highest-impact discrepancies. Example: “spine is occluded at 50% and active leaf overlaps price panel”, not “needs polish”. Rank by identity, comprehension, function, then detail.
7. **Modify one coherent issue group:** preserve prior good version; rerun the same captures. Do not regenerate all assets for a local correction.
8. **Compare:** check target versus actual and before versus after; test one neighboring state so the improvement is not limited to a single shot.
9. **Measure:** when visually credible, check device budgets and degrade secondary cost first (map sizes/DPR/shadow quality/hidden geometry), preserving silhouette and key light.
10. **Close a phase:** save source, exports, screenshots, measurements, known limitations and next objective. A passing build alone is not visual completion.

Two or three focused visual passes per bounded issue are a starting allocation, not a forced stop with known defects. If an approach stalls, record the evidence and change the approach instead of issuing repeated vague polish requests. Use early cheap preview renders; high-quality output only after structure is settled.

## Plus usage strategy

No creator quota percentage is treated as predictive. This plan makes no assertion about the user's current remaining limit or five-hour allowance. Choose effort through the current UI and actual available allowance; reserve higher-effort Astra work for art direction, difficult spatial problems and cross-system visual diagnosis. Do not default every task to maximum simply because reference A used it.

A coherent session finishes an inspectable product slice. Routine code implementation can happen between Astra sessions from the contracts, with Astra reviewing the integrated output. Avoid simultaneous expensive agents by default; parallel work is optional only for clearly bounded independent tasks when explicitly authorized, not assumed necessary.

At the start of a session, state the highest-priority outcome. When allowance is becoming constrained, stop adding scope and write a checkpoint while work is still coherent. Never spend the final capacity on a trailer while source assets or handoff are missing.

## State to retain after every phase

- Repo/branch/commit and exact run commands; changed-file summary; actual deployment status.
- `docs/VEYA_MASTER_HANDOFF.md`: short current truth; append links to changed specifications.
- `docs/session-log.md`: objective, result, evidence paths, passed/unpassed gates and next action.
- `docs/decisions.md`: decision, reason, alternatives rejected, date, owner, reversibility.
- Source .blend/scripts, web assets and manifest with versions/checksums/licenses.
- Named screenshots at desktop/mobile plus short behavior capture; target reference and critique log.
- Current approved commercial catalog and version; open business questions; no credentials.
- Test commands/results and real-device measurements with environment details.

A fresh session receives the concise handoff, current commit, one target image and current screenshots, then reads only the spec relevant to its phase. Do not repaste the entire master brief and repeat research.
